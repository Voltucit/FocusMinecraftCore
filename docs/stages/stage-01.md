# 第 1 阶段：基础版本查询与继承解析

状态：已完成。完成日期：2026-10-24。

## 本阶段完成标准

- 从指定根目录或约定的自动发现位置读取本地版本。
- 提供列表查询与按 ID 查询两个独立公开接口，返回版本对象。
- 区分 JSON ID、实际版本目录和父版本 ID。
- 查询保持只读；不存在的查询目录不自动创建。
- 解析同一根目录内的继承链，明确报告缺失、重名和循环。
- 按子版本优先规则解析 mainClass。
- 通过当前自动化测试、真实元数据读取与独立公开 API 示例，并交付中文文档。

## 已实现的公开入口

导入路径均为 `fmcore.versions`：

- `MinecraftVersion`
- `get_versions()`
- `get_version()`
- `get_inheritance_chain()`
- `resolve_main_class()`

详细签名与异常见 [公开 API 清单](../public-api.md)，调用说明见 [版本模块手册](../versions.md)。

## 验证记录

2026-10-24 已运行现有 6 条自动化测试，全部通过：

1. 三层继承。
2. 循环继承。
3. 父版本缺失。
4. 父版本 ID 重名。
5. 目录名与 JSON ID 不同的真实临时文件读取。
6. 多根目录汇总、同 ID 保留、查询歧义与明确根目录选择。

前四项基于内存对象；后两项基于临时文件系统，多目录用例模拟工作目录与 APPDATA。它们不等同于真实游戏启动。

真实文件读取已检查本地 1.21.1、1.8.9、26.4-snapshot-2 的基础字段。1.21.1 元数据来自此前下载的官方版本清单；本轮读取的是本地副本，没有重新做在线安装或启动验证。

4 个独立示例均已执行，共 16 个 CLI 验收场景通过，涵盖帮助、正常调用、参数错误、缺失、重名、损坏 JSON、循环、入口缺失和显式目录优先。失败场景以预期非零返回码通过验收，没有跳过错误。

另外使用临时目录验证了跨根目录父版本隔离、缺少本地父版本时拒绝借用其他根目录、子版本入口覆盖及入口继承。检查了 9 个 Python 源文件、8 段文档 Python 代码的语法和 13 处本地文档链接。

这些属于本地文件和受控环境验收，没有执行游戏安装、Java 启动或包发布。

## 当前限制

- 仅解析基础展示字段、继承关系和 mainClass；未合并 libraries、assets 或完整启动参数。
- JSON 文件名要求与所在版本文件夹同名。
- 损坏的候选 JSON 会使整个查询失败，暂未提供部分结果和逐项诊断对象。
- get_version 复用整个查询范围的列表读取，其他候选 JSON 损坏也会使单版本查询失败。
- 查询模型和元数据可读不能证明文件可信或游戏可启动。
- 尚未配置 Python 包构建、PyPI 分发及第三方项目安装验证。
- 未执行真实游戏启动，不宣称各加载器已经兼容验收。
