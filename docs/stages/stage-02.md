## 当前公开用法

`LaunchConfig → new MinecraftLauncher(config) → LaunchAsync(ReportProgress)`。

LaunchConfig 包含账号、游戏、Java 和可选窗口分组。入口负责读取版本、探测指定 Java、组合 PreparedLaunchConfig，并复用已有依赖、资源、参数、原生库和进程逻辑。原构造式配置已改名为 PreparedLaunchConfig，静态高级入口继续保留。

## 旧式 Windows 原生库定位小阶段：已完成

完成日期：2026-10-25。第 2 阶段整体仍在进行，尚未启动 Minecraft。

### 内部方法与职责

| 方法 | 用途 |
| --- | --- |
| ReadNativeClassifier | 读取指定系统的原生库分类名称，未声明时返回 null |
| ExpandNativeClassifier | 根据选定 Java 的 x86/x64 架构替换旧式 ${arch} |
| GetWindowsNativeLibraryPath | 按 Windows 规则选中分类下载项，返回安全的绝对路径 |
| GetWindowsNativeLibraryPaths | 汇总当前版本的路径，去重，并报告缺失文件 |
| ResolveLibraryPath | 私有共用步骤，供普通依赖和原生库复用路径检查 |

这些方法不属于公开 SDK。本小阶段没有新增 public API。后续由公开启动入口统一编排，启动器无需手动调用这些内部步骤。当前公开入口见 [API 清单](../public-api.md)。

### 验证结果

- 正式项目保存并通过 53 项 Release 自动化测试，0 失败、0 跳过。其中新增原生库测试为 12 项。
- 新测试使用受控 JSON、JavaInfo 模型和独立临时目录，包含真实临时目录联接点的越界检查。
- 本机真实 1.8.9 与明确指定的 Java 17.0.9（x64）只读核对通过，定位到 4 个已存在的原生库 JAR。版本 JSON 保持原样。
- Java 17 在这里仅用于架构和路径核对，不代表推荐用它启动 1.8.9。
- Windows 上进程结束后，测试文件可能短暂访问受限。TestFiles 清理自建临时目录时最多尝试 20 次，每次间隔 50 毫秒。持续失败仍抛异常。独立验证了短暂锁释放与持续锁报错，没有放宽业务断言。

### 定位小阶段验收时的范围

只处理当前版本自身带 natives、downloads.classifiers 和明确 path 的旧式 Windows 声明。Java 架构限 x86/x64。没有原生库声明时返回空结果，不猜测未知架构。

定位小阶段验收时尚未合并父版本依赖；现已接入，见后文。更旧的无下载元数据格式和新版普通 artifact 原生库识别仍未支持。定位验收时未下载、校验 JAR 内容、解压或启动游戏；后续解压结果见下节。x86 的验证来自受控模型，没有真实 32 位游戏运行证据。

## 原生库安全解压小阶段：已完成

完成日期：2026-10-25。用户亲自写入 NativeExtractor.cs，验收未修改业务实现。

- 内部 ExtractWindowsAsync 保留逐条 extract.exclude，预检全部条目后写入版本目录下的本次专用 natives 目录；空结果返回 null。拒绝越界、链接、保留名称和重名冲突，不覆盖文件。
- 限制压缩包、条目和解压大小；写入时核对实际长度和 CRC32。取消或失败仅清理本次创建内容；清理错误不会被吞掉。详细上限和异常边界见启动手册。
- 正式 Release 测试 90 项通过，0 失败、0 跳过。其中新增解压测试 37 项，包括真实临时目录联接点、写入失败回滚和输出出现后的取消。
- 真实 1.8.9 的 4 个 JAR 在隔离目录解压出 14 个 DLL；SHA-256 与包内文件逐项一致，原始 JSON 和 JAR 未改变。本轮仅使用 x64 JavaInfo 模型，没有启动 Java、DLL 或游戏。
- 不含清单 JAR 哈希认证、恶意本地目录替换竞争防护或成功目录的生命周期回收。不新增公开入口，后续由启动 API 编排。

## 依赖继承、classpath 与客户端 JAR 小阶段：已完成

完成日期：2026-10-25。代码和测试由用户亲自写入，测试及真实样本验收由用户执行。

- 内部 GetWindowsLibraryEntries 按同根继承链合并依赖，先筛选 Windows 规则，再采用子版本整条覆盖父版本的策略；分类和扩展名分别保留。同层不同声明冲突报错。
- 内部 GetClientJarPath 按元数据选定客户端，支持一次显式 jar 版本引用及父版本客户端。按实际目录名定位文件，拒绝越界和缺失；不因缺文件换用其他客户端。
- 内部 GetWindowsClassPath 检查普通依赖和客户端存在性，按实际路径去重，Windows 分号连接，客户端最后。原生库专用分类文件不加入 classpath。
- 原生库定位和解压已接入合并后的依赖，继承 extract.exclude。
- ClassPathTests 新增 15 项受控测试；用户反馈测试成功，未提供对应 TRX 的总数，不将预期 105 项当作已核实总数。
- 用户运行本地 ClassPathCheck，真实 1.8.9 输出 32 项 classpath、4 个原生库包、正确客户端路径、MetadataUnchanged: True、GameStarted: False。核对文件存在、路径无重复、客户端最后及元数据 SHA-256 不变；没有启动 Java 或游戏。原始用户输出见本地 docs/validation/classpath-live-user-output.txt。
- 无新增 public API，不宣称已覆盖所有加载器特殊合并规则或完成 JAR 内容真实性验证。
