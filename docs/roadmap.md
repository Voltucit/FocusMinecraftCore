# FMCore 2.0 开发路线

开发环境为 Python 3.13、Windows 10/11；核心与 Python 启动器界面分离。每阶段完成时交付公开 API、中文文档、独立示例、验证结果和已知限制。

| 阶段 | 目标 | 当前状态 |
| --- | --- | --- |
| 1 | 基础本地版本查询、JSON 解析、版本对象、继承链、启动入口继承 | 已完成（2026-10-24） |
| 2 | 启动一个已安装完整的原版：Java 检测、离线身份、依赖与启动参数、进程和日志 | 待开发 |
| 3 | 下载与原版安装：进度、取消、重试、校验、资源补全 | 待开发 |
| 4 | Java 下载与安装、Microsoft 登录与刷新、Yggdrasil 协议接入 | 待开发 |
| 5 | Forge、Fabric、NeoForge、OptiFine 安装 | 待开发 |
| 6 | Modrinth、CurseForge 查询、图片、依赖、安装与更新 | 待开发 |
| 7 | 整合包格式识别、安装、导出、整体更新与失败恢复 | 待开发 |
| 8 | 完善诊断、综合示例、文档和 Python 包发布准备 | 待开发 |

日志、安全校验、测试与开发者 API 易用性随功能推进。阶段 8 再集中完成发布验收。

## 第 1 阶段边界

本阶段读取用于展示与继承关系分析的基础元数据，并解析单个继承字段 `mainClass`。不要求完成整个版本 JSON 的合并，也不据此判定版本已经可启动。

完整的 libraries、assets、原生库、旧版与新版启动参数和 Java 命令将在启动与安装阶段处理。

## 已确定的长期要求

- Minecraft 根目录由调用方显式指定，或在查询时使用已约定的有限范围自动发现。
- 查询保持只读；安装等写入操作自动创建必要目录，并处理安全校验和失败恢复。
- 新建隔离实例采用 `versions/<版本或实例名称>/`，启动版本 ID 与实例目录名称分别管理。
- assets、libraries 等公共文件可以共享，mods、config、saves 等实例数据按工作目录隔离。
- 已有外部目录保留原结构，兼容能力通过实际元数据与测试逐步验证。
- 支持的加载器安装范围不包含 LiteLoader；不实现 Minecraft 基岩版检测和启动。
- 阶段完成不表示授权推送、创建 Release 或发布包。
